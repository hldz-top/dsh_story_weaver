# Stage execution

The executor uses the installed DSH 0.2.2-rc.3 native spawn, ToolRuntime, AgentLoop and JSONL Session persistence. Keyless integration tests verify stage execution; complete writing and browser validation remain separate acceptance work.

## Ownership

`executeStage(ctx, exec, request, config)` consumes the host's existing subagent runtime for stages that call tools. The writing run owns the durable attempt before calling this function. The executor starts a fresh child through `ctx.subagents.startActivation` with `delivery: 'caller'`, no `agentOptions`, and no `toolFilter`. It captures the child Agent from `subagent/start` before the prompt is submitted, restricts that child's global tools, associates its Session, awaits the activation result, and disposes that activation before returning. It does not create an AgentLoop or call a model adapter directly.

`executeDirectStage` is the other path. Research planning, candidate generation (including the body and continuity), and their repairs only read already selected inputs and write text, so they call the host `ctx.llm` service once. The call inherits `agent.model.current()`, sends no tools, and streams one request. `BlockAssembler` aggregates the text. The runner writes the model-visible prompt and the raw reply under the current Session's preview directory before the stream and after a schema-valid reply. A generation id is stored on the attempt so provenance stays unique; no subagent Session is created. Review, citation repair, and research still use `executeStage` because they call `story_read_artifact` or research and web tools. A schema-invalid or undecodable reply is `stage-malformed`. A refusal, length cut-off, missing text, deadline, and a failed audit write stay distinct failures. The plugin does not register a provider adapter or an external gateway.

The configured provider must be the deployment's verified in-process spawn provider on DSH 0.2.2-rc.3. DSH checks the requested output-schema and depth-limit capabilities before preparation. Spawn children are continuable activations. The executor requires the `subagent/start` event to resolve a live local Agent and rejects the stage when that Agent is absent, then disposes the activation. A remote provider can already have started before that check. Deployment validation must establish the provider type before live use.

## Inputs and result

| Field | Meaning and downstream path |
| --- | --- |
| `ctx` | The host context exposing the shared subagent, Agent, Session, and LLM event capabilities. |
| `exec` | The actual parent ToolRuntime execution. Its Agent supplies lineage and the inherited model route; its signal owns cancellation. Agentless calls are rejected. |
| `request.attemptId` | The unique identity of a previously persisted attempt. Recorded as the child's continuable descriptor label. The run owner must not reuse a live attempt ID. |
| `request.prompt` | A self-contained stage task with exact input versions and bounded evidence. Delivered as a logged child user message. |
| `request.outputSchema` | An object-root JSON Schema accepted by DSH's existing schema validator. The native child `structured_output` tool enforces it. |
| `request.onStarted(childSessionId)` | The owning run's durable association callback. It must persist the child identity before the executor admits its first model stream. Failure prevents generation and triggers awaited disposal. |
| `request.authorizeTool(execution)` | Optional asynchronous native tool admission for this exact child. The callback runs after durable association and before native side effects; rejection becomes a native tool error. Permission must derive from the recorded stage request. Its listener is removed after child disposal. |
| `config.stageProvider` | The registered in-process spawn provider name; this is not a model or LLM provider selection. |
| `config.maxDelegationDepth` | A non-negative safe integer passed as the absolute child delegation-depth cap. It does not count model requests. |
| `config.allowedTools` | Global tool names passed to `child.ctx.tools.restrict({ allow })` during `subagent/start`, before the prompt is queued. `structured_output` stays visible because it is registered in the child scope and must not be named in `allow`. Unknown global names fail the host restriction. Scoped registrations are not removed by `restrict`, so before every child model request the executor checks `tools.schemas(child)` and fails with `stage-tool-scope` when any tool outside the allow list and `structured_output` is visible (`run_code` is exempt). Before every child tool execution it rejects any tool outside that set, including `run_code` sub-dispatches. |
| `config.maxStageRequests` | A positive safe integer bounding child model dispatch attempts, including retries. |
| `config.stageTimeoutMs` | An integer from 1 through 2147483647 covering startup, association, generation and disposal. Expiry propagates cancellation and still awaits owned work, including an association callback already in progress; it does not forcibly abandon persistence or cleanup. |
| `result.childSessionId` | The exact child Session containing the logged prompt, requests, tool calls and structured capture. |
| `result.structured` | The value captured by the native structured-output tool after a completed child turn. Stage-specific domain parsing remains the caller's responsibility. |

The executor passes no `agentOptions` override. DSH 0.2.2-rc.3 inherits the parent request's provider, model, and reasoning effort. `delivery: 'caller'` returns the result without injecting a `subagent-settled` notice or waking the parent; a local child still appends `subagent/catalog` on the parent Session. The startup `signal` cancels only before publication. After publication, cancellation calls `activation.dispose()`. The executor does not silently select another model, substitute a provider, accept plain assistant text as structured output, or replace a missing value with an empty object.

## Writing-stage schema publication

`nativeStageOutputSchema(kind)` derives each native schema from the matching entry in [`StageOutputSchemas`](../../src/stage-output.ts). The `kind` selects settings, review, book outline, chapter outline, body or continuity. Its returned object goes directly to `request.outputSchema`; the logged native tool definition exposes the same instructions to the child.

The installed DSH schema dialect enforces object properties, required fields, additional-property rules, arrays and items, scalar types, enums, constants and supported `oneOf` branches. The adapter preserves those fields and existing annotations, then calls DSH's `assertObjectJsonSchema`. It omits the root JSON Schema dialect label and Zod's non-enumerable `~standard` compiler metadata. Zod's emitted `minLength`, `minItems`, `pattern`, `exclusiveMinimum` and `maximum` constraints become explicit field descriptions because this DSH dialect does not enforce them. Every other unsupported keyword rejects publication with its schema path; the adapter does not discard unknown constructs or replace them with unconstrained values.

`projectNativeStageSchema(schema)` exposes this compiler adaptation for an object schema and returns the validated native object schema. It rejects malformed native fields and cyclic schema references. It is not the output admission validator. The run must still pass every captured value through the original stage parser, which enforces the original constraints, nonblank text, exact input versions, stage identity, required checks and quoted evidence. Chapter-total counting and application remain host-owned. Native structured capture alone cannot approve a candidate.

## Model request accounting

The admission listener uses the public `llm/stream` waterfall because it surrounds actual dispatch attempts, including retries within one AgentLoop step. `agent/request`, output token limits and delegation depth do not establish the same bound.

`startActivation` submits the prompt before it returns. A `subagent/start` listener therefore captures `ctx.agents.get(info.id)` and applies the tool restriction before that prompt, matching the continuable descriptor label. A `session/event` listener also records that descriptor. The stream listener then checks that child Session ID, waits for the durable association callback, checks cancellation and increments the attempt count before delegating with `next()`. Concurrent stage attempts must have separate identities, counters and disposal, and ordinary parent or unrelated child requests must remain unaffected.

The count covers the direct child Session. The stage tool allow list must prevent descendants or tools from independently dispatching additional model work. This measures admitted model dispatch attempts, not currency or a provider's final invoice. An adapter or external service may have accounting behavior outside this plugin's observation. Report provider-returned usage from child Session evidence separately; absent usage is unknown.

## Failure and recovery

Non-completed stop reasons, missing structured capture, budget exhaustion, timeout, cancellation and callback failure remain failed attempts. Cancellation is checked before start and again after child disposal so a late result cannot be published as success. The durable writing service rechecks its own run and input-version state before persisting or applying the returned candidate.

After an activation is published, every exit path awaits `activation.dispose()`. A later dispose joins the same close. Execution and disposal failures retain their separate causes, using `AggregateError` with the execution failure as `cause` when both fail. Aborting the startup signal after publication does not stop the child; the abort listener calls `dispose()`. Temporary model-stream, tool-admission, child-capture and Session listeners and the deadline timer are removed after owned child work settles. A start rejection before publication has no activation to dispose.

Plugin-owned errors have stable codes: `stage-config` for invalid finite limits or an empty provider name; `stage-audit` when a direct stage cannot store its prompt or output on the current Session, or a stored input digest does not match; `stage-provider` when `subagent/start` does not yield a live local Agent; `stage-budget` for an exhausted dispatch allowance; `stage-timeout` for deadline expiry; `stage-malformed` when the child turn ends with DSH's `MALFORMED_RESPONSE` error code (a received model response that DSH could not decode, such as invalid `structured_output` JSON) and no structured capture; `stage-refused` when the provider declined the request (a `refusal` stop reason, a `REFUSAL` or `CONTENT_FILTER` failure code, or DSH 0.2.0-rc.2's DeepSeek Messages `MALFORMED_RESPONSE` for an `unsupported stop reason refusal` or `content_filter`, which is a refusal rather than a decoding defect); `stage-truncated` when the child's output stopped at the model's output-token limit, even if a structured value was captured before the cut-off; `stage-missing-result` when the child's turn ends normally (for example with plain assistant text) without calling `structured_output`; `stage-tool-scope` when the child can see or tries to call a tool outside its allow list, such as a subagent dispatch tool; and `stage-incomplete` for any other non-completed result or missing structured capture. A refusal or truncation is never reported as success, as an empty value or as a generic incomplete stage. The writing runner records a `stage-tool-scope` or `stage-audit` attempt as a known failure, not an unknown outcome, and does not retry it. Native startup, association and disposal errors retain their original values. The child Session preserves detailed model and tool failure evidence.

The continuable activation allocates the child id inside `startActivation`. The run owner records provisioning first and treats a crash before durable child association as outcome unknown. The executor does not automatically resend that attempt. Durable recovery, stop/resume and late-commit prevention belong to the writing-run service.

## Verification

[`tests/stage-executor.spec.ts`](../../tests/stage-executor.spec.ts) exercises the real parent tool and native child path with a scripted model adapter. Its cases cover structured success and inherited route, persisted prompt and child association, invalid structured-output retries, actual provider retries within one loop step, independent concurrent stage budgets, finite configuration, unsupported capabilities and unknown references, missing local Agent metadata, association failures, pre-start and in-flight cancellation, cancellation during disposal, deadline expiry, missing structured capture, model error and token exhaustion, and execution/disposal failure preservation. Tool-admission cases verify rejection before side effects and removal before another child executes. Tool-scope cases register a delegation tool in the child's own scope and verify that the stage fails before any model request, that a delegation tool appearing mid-stage is never executed, and that allowed artifact tools stay visible. Every published-child scenario asserts that no child Agent remains. An external provider that returns the official run handle without a local Agent is rejected after disposal. The official spawn provider does not expose a way to force `dispose()` to reject, so that aggregate path stays in the executor without a separate scripted failure.

Run the focused suite with `node node_modules/vitest/vitest.mjs run tests/stage-executor.spec.ts --configLoader runner --cache=false`. It performs no external model calls. Scoped TypeScript and oxlint validation also cover the executor and its fixtures.

[`tests/native-stage-schema.spec.ts`](../../tests/native-stage-schema.spec.ts) adds 27 cases covering all six schemas through the installed validator and actual native child structured capture, inherited routing, strict structural rejection, preserved constraint descriptions, canonical rejection after capture, unsupported constructs and malformed topology. Run it with `node node_modules/vitest/vitest.mjs run tests/native-stage-schema.spec.ts --configLoader runner --cache=false`.

Real-model quality and the complete browser writing path remain part of [post-development validation](../development/post-development-validation.md).
